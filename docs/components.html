Components

What each project is for, grouped as the source tree is. The pages before this one follow the jobs; this one follows the code, for the reader who has a project name and wants to know where it fits.

A project is one of three kinds. A library is linked into others. A DLL is loaded into a process, usually injected into the program that is being studied. A program is started by a person. The ones a person starts are APIDumper and APIDumpPrinter. The rest is used by those, and by any project that has this one as a submodule and builds on its libraries.

Interception: hooks and core

These are the parts that sit inside the program that is studied. A hook is the replacement of an entry point of an API: it calls the callbacks registered for it, then the real function, then the callbacks again. What the callbacks do (write a dump, or whatever a project that builds on this one needs) is for the DLL that registers them, not for the hooks. Each hooked entry point is named ai<ApiName>.

APIInterceptor (Common)

Library of objects, compiled into every DLL that hooks. The machinery that does not depend on an API: the registry of callbacks that run before and after each function, the gate that stops the interceptor from seeing its own calls, the store of the data chunks that a call carries, the logger, the failure of unsupported values (AI_FAIL_UNSUPPORTED), and the types of the workload file. Its namespace is APIInterceptor.

D3D8, HooksCommon, OpenGL, WGL, GDI32, User32, Kernel32

Libraries, one for each set of entry points.

  • D3D8 hooks Direct3D 8 through the tables of methods of its objects. Besides the entry points it has the policy of what is hooked and the modification of typed arguments. What it shares with the other COM-based APIs is in HooksCommon; it adds its traits to it.
  • HooksCommon (Interception/Hooks/Common) is what the hooks of the APIs made of COM objects have in common: the hook of a function exported by a DLL, found once the DLL is loaded; the registry of the patched tables of methods, and the table of hooks that fills them; the hook of one method, which an API tunes with its traits (how its arguments are stored, the extra data and bookkeeping of a method, which call ends a frame); the capture of arguments by category; and the tracker of locks, so that the data a program writes into a buffer or a surface is known when it is unlocked.
  • OpenGL hooks the functions of each version and extension, a directory for each. It keeps the state that is per context in a registry of contexts.
  • WGL hooks the creation and the use of OpenGL contexts on Windows.
  • GDI32 hooks the choice of the pixel format and the swap of buffers; User32 hooks the creation of windows and device contexts. Together with WGL they are what a workload needs to put the window and the context back at replay. They do not draw.
  • Kernel32 hooks LoadLibrary and ExitProcess: the first to notice an API that is loaded after the program starts, the second to know when the process ends.

D3D8Utils and OpenGLUtils

Libraries, in Interception/Core. The knowledge of an API that is not a hook. D3D8Utils describes the Direct3D 8 interfaces and methods (the table of methods, the traits and kinds of arguments, readers of values, the layout of the pixels of a surface). The hooks, the printer and any project that reads a workload all read it, so that none of them keeps its own list. OpenGLUtils is the corresponding, smaller helper for the enums of OpenGL.

Capture

Recording what a program does into a workload file. See Capture.

APIDumper

Program. Starts a program with APIDumperDLL injected. It does not record anything itself.

APIDumperDLL

DLL. Registers callbacks on the hooks and records every call with its arguments and data chunks, and the images of the back buffer of Direct3D 8 (d3d8_swapchain_reader). The calls are cut into segments and compressed with Zstd by a writer thread, so that a program is not slowed down by the disk.

APIDumpLoader

Library. Reads a workload. WorkloadReader takes it segment by segment, so that a workload larger than memory can be read; api_info says which API group a call belongs to and which calls end a frame. The replay engine and the printer read workloads through it.

APIDumpPrinter

Program. Prints a workload as text, every call with every argument. It has the names of the calls and enums of each API, and a decoder of the arguments. It is for reading what a program did, and nothing else.

InjectionLauncher

Library. Starting an application with a DLL in it, used by the dumper, and by any project that has to start a program with a DLL in it. It reads the executable to know its architecture, injects with Detours while the application is suspended.

Replay

Executing the calls of a workload again, without the program: to check that a capture is complete, and as a test of the captures that the dumper makes.

ReplayEngineDLL

DLL, built for 32 and 64 bits. The replay engine. It walks the calls of a workload and hands each to the executor of its API (Direct3D 8, OpenGL, Win32 windows, or one that does nothing). It remaps the objects of the dump onto the live ones, restores the arguments a call needs, replays locks and client arrays, and paces the frames. The executors are the parts that depend on an API.

ReplayPlayer

Program. A control window (Dear ImGui) around the replay engine: choose a workload, play and pause. A 64-bit player starts the 32-bit one for a 32-bit workload.

Tests and third-party code

APIInterceptorTests

Program. The tests, with googletest, of every library above. The helpers shared with a project which builds on this one (the path of the program that runs the tests, the names of sessions) are Tests::Fixtures, a library of their own, APIInterceptorTestSupport. See Building.

deps

Detours (built by Detours_AI) for hooking and injection; Dear ImGui for the window of the player; Zstd for the compression of workloads; googletest; and the Khronos headers of OpenGL.
